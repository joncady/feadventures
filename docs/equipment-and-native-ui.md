# Equipment model and native UI

The compact right-side panel uses the Awakening Text Boxes sheet (https://www.spriters-resource.com/3ds/fireemblemawakening/asset/80213/), existing portraits and standard weapon icons. Its portrait, level/EXP, HP, combat values, vertical stat list, five inventory rows and ally orders follow the supplied character-screen reference. The local FE.otf identifies itself as FOT-Chiaro Std B; it is loaded before Phaser creates text. This is the bundled project font, not a separately verified exact match for every localized Awakening UI font.

All visible battle HUD elements are Phaser objects: status, notices, instructions, pause/resume, main menu, audio controls and sliders, mute icon, fullscreen and game-over screen. A separate Interface scene keeps controls active while Arena is paused. Visually hidden HTML mirrors retain keyboard and screen-reader access and share handlers with the native controls. The character-selection screen remains HTML.

## Multiple weapons

Keep four concerns separate:

- Character: stats, class and weapon proficiencies/ranks.
- Weapon definition: stable ID, type, required rank, might, hit/crit, minimum/maximum range, attack timing, animation/projectile, effects and sound.
- Inventory instance: weapon definition ID, remaining uses (null means unlimited in survival), upgrades and ownership. Up to five slots; consumables should share the inventory through a discriminated item type.
- Equipped slot: one index into the inventory, validated against class permissions, rank and remaining uses.

src/game/data/equipment.ts scaffolds shared weapon definitions, five-slot loadouts, class permissions, and validated equipment selection. The HUD displays the initial loadout and empty slots. Combat still uses the existing single-weapon hero profiles; switching weapons during battle is not enabled in this batch. Weapon ranks are a future validation layer.

Before enabling switching, give Arena a run-local loadout and one derived equipped-combat profile. Route range, damage, cooldown, aim, triangle, resistance, icons and sounds through that profile. Lock the selected weapon into each pending attack/projectile so changing equipment cannot alter a shot already fired. Equipping must not reset cooldowns. Character stats/XP should remain independent of equipment; physical and magical attacks select Strength or Magic plus weapon might. Click an inventory row or cycle with E; Q remains ally orders. Add meaningful coverage for switching melee/ranged/magic during windup and respecting class/rank restrictions.

## Audio

Music defaults enabled at 18% and starts when the browser unlocks audio on user interaction. Mute and separate music/effects/voice levels remain available in the native audio panel.

Begin Battle plays WARC_SYS_FIRST_0.wav from the downloaded battle effects archive (https://sounds.spriters-resource.com/3ds/fireemblemawakening/asset/401959/), under the effects volume. Restart uses the same cue.

No verified waveform/spectral match for the supplied level-up reference was found in the local effects archive. level-up.wav now uses the supplied reference (https://www.youtube.com/watch?v=aw-CaOiuMco), converted to mono PCM with only leading/trailing silence removed. The local original is retained as asset-library/awakening/level-up-reference.m4a; scripts/prepare-ui-audio.mjs reproduces the WAV using Playwright Chromium. The XP tick remains generated by scripts/prepare-progression-audio.py, which no longer overwrites the imported level-up sound.
